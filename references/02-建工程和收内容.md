# 第 2–3 步：建工程、收内容

## 第 2 步：建工程

一次只问一件，按这个顺序问（用户一句话里已经说了的就不再问）：
1. **放在哪？**：给两个选项，「桌面」或「你指定一个文件夹」。用户说「随便」就放桌面。
2. **横屏还是竖屏？**：横屏 1920x1080，适合 B 站、YouTube、小红书横版；竖屏 1080x1920，适合抖音、小红书竖版。
   用户说不清时看他的口播视频：竖着拍的建议竖屏。
3. **片名？**：几个字就行，用户不想起就用默认值。

```
python new_project.py "<放在哪>" --name "<片名>" --orient 横屏|竖屏
```

脚本会在指定位置建 `YYYY-MM-DD_片名/`，自动打开这个文件夹，最后一行是 `PROJECT=<路径>`。之后的命令都在 `<路径>/_工程/` 里运行。

| 文件夹 | 放什么 | 谁放 |
|---|---|---|
| `1_口播稿/` | 口播稿：docx、rtf、txt、md；也可以是三列脚本表（口播词 / 画面 / 参考资料，模板在 `<技能>/模板/`） | 用户 |
| `2_口播视频/` | 口播视频（手机、相机拍的都行）；只有录音也行（mp3、m4a、wav） | 用户 |
| `3_素材/` | 用户自己的图片、视频、截图、录屏 | 用户 |
| `3_素材/找来的/` | 第 4 步下载的素材 | AI |
| `4_参考图/` | 想要的画面感觉；文件名带「调色」的那张拿来调色 | 用户（可以不放） |
| `5_BGM/` | 背景音乐，放一首就自动用（默认不加音乐） | 用户（可以不放） |
| `_工程/` | 剪辑脚本和中间文件 | AI |
| `成片/` | 交付的东西 | AI |
| `修改表.xlsx` | 看完片子要改的地方 | 用户 |

**停下来**，跟用户说：
> 文件夹建好了，已经帮你打开。请把这几样放进去：
> 1. 口播稿 → `1_口播稿`
> 2. 口播视频 → `2_口播视频`（分几段录的就都放进去，按文件名顺序接起来）
> 3. 你自己的图片、视频素材 → `3_素材`（没有可以不放）
>
> 放好了跟我说一声。

## 第 3 步：收内容

```
python intake.py
```

它读口播稿（存成 `_工程/口播稿.txt`）、检查每个视频和素材（存成 `_工程/媒体信息.json`），打印一份报告。最后一行 `TAKE=<路径>` 是第 5 步要用的口播原片：只有一条就是它本身，有好几条就是按文件名顺序接好的 `_工程/口播_合并.mp4`（只有录音时是 `口播_合并.wav`）。把报告翻成大白话告诉用户，重点说这几件：
- **口播视频**：几条、多长、横的还是竖的。
- **方向不一致**：比如竖着拍、要做横屏，人物全屏时要放大裁切，会有点糊。问用户是改成竖屏，还是就这样。改的话改 `_工程/project.json` 里的 `orient`。
- **多条口播**：已经按文件名顺序接成一条；顺序不对，请用户改文件名（比如前面加 1_、2_），再跑一次 `intake.py`。
- **停留 N 秒**：口播稿里写了「（画面…停留3秒）」这种舞台说明，报告会数出来。这些是给画面看的，不念出来，做画面时那一页要停够秒数（`hold=N`）。
- **用的是三列脚本表**：「画面」那一列就是用户想要的画面，做第 4 步和第 8 步时照着来。

`intake.py` 退出码是 1：说明没有口播视频，请用户放进去再说。

口播稿不改字。用户的原始文件只读，不改、不删、不移动。
